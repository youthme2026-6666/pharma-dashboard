# 医药行业财务看板 · 自动维护说明书

这份说明书写给两类读者：负责维护的程序（每天由 GitHub Actions 运行，判断性的工作交给 GPT），以及以后要改这套东西的人或编程助手。第 0 部分是多公司框架；第 1~12 节是礼来细数据流程（`lilly_deep` 适配器），其他公司的适配器沿用同样的原则。

> 一句话：每天逐家公司检查官方新申报（SEC、港交所、巨潮）；有，就按固定规则解析成统一格式、逐项核对，全部通过才写进 `data/<公司>/`；GPT 负责新增公司、读只能读 PDF 的报告、找重大事件这类需要判断的事，而且它的每条输出都要通过代码里的核对才会被采用；最后重新生成网站，发布到 GitHub Pages。某家公司出问题只影响它自己，并自动开 GitHub issue。

---

## 0. 多公司框架

### 0.1 目录

| 路径 | 作用 |
|---|---|
| `companies/registry.json` | 公司清单：中英文名、分类（9 个方向）、地区、各上市地代码、数据来源（适配器）、币种、财年截止月、批次、状态（active 已上线 / onboarding 接入中 / planned 待接入 / paused 暂停）。格式规则见 `agent/core/registry.py` |
| `companies/watchlist.md` | 想加的公司写一行（名字或代码），由 GPT 自动核对接入（第 4 阶段实现） |
| `data/<公司>/` | 统一格式数据：`income.csv`、`balance.csv`、`cashflow.csv`、`segments.csv`、`events.json`、`meta.json`。礼来另有 7 份细数据（第 2 节） |
| `state/<公司>/` | 每家公司的运行状态（已处理的报告、回测结果、上次检索事件的日期等）；`state/global.json` 记每月 GPT 花费 |
| `agent/core/` | 框架：公司循环（`run.py`）、清单（`registry.py`）、统一格式（`schema.py`、`store.py`）、报告（`report.py`）、网站（`site.py`） |
| `agent/adapters/` | 数据来源适配器，接口见 `base.py`；`lilly_deep.py` 调用 `agent/pipeline/` 的礼来流程 |
| `agent/glossary.json` | 中英术语表，页面上的指标、报表行、图例都显示“中文 English” |

### 0.2 统一数据格式（所有适配器的约定，详见 `agent/core/schema.py`）

- 金额单位一律为**百万**（报告币种，`currency` 列写明），每股收益为每股多少元，股数为百万股；没披露的留空，不填 0。
- 期间：`fiscal_year` + `fiscal_period`（Q1~Q4 / H1 / H2 / FY）用公司自己的财年口径；`period_end` 为期末日期，横向比较按它对齐；`months` 为期间月数。
- `basis`：reported（原文直接给出）或 derived（推算：第四季度 = 全年 − 前三季度，下半年 = 全年 − 上半年，单季现金流 = 年初至今相减）。
- `source`：数据出处，方便追溯。
- 核对：毛利 = 营收 − 营业成本，净利润 = 税前利润 − 所得税，资产 = 负债 + 权益，四个季度之和 ≈ 全年；不平就整家公司本次不写入。

### 0.3 每天的流程（`python -m agent.core.run auto`）

1. 读公司清单并核对格式。
2. 逐家处理状态为 active / onboarding 的公司：按 `source` 调用适配器的 `update`，得到统一格式的行和核对结果；有“必过”项不通过，或统一格式勾稽不平，这家公司本次不写入，报告里记为“需要处理”，其他公司照常。
3. 统计每家公司的 GPT 用量和估算花费，累加到本月；超过每月上限（`config.json` 的 `gpt.monthly_budget_usd`，默认 15 美元）后暂停重大事件检索，财务数据照常更新。
4. 生成网站：首页 `_site/index.html`（9 个方向的公司目录，已上线公司显示最近一期营收、同比、毛利率、营业利润率），每家公司的页面 `_site/c/<公司>/`，统一格式数据下载 `_site/data/<公司>/`。
5. 写报告 `agent/output/report.md`；工作流提交 `data/`、`state/`、`companies/` 的变化并发布网页；有“需要处理”的问题时开或追加 `dashboard-bot` issue。

手动运行的其他模式：`backtest`（逐家回测解析器）、`check`（核对清单和数据）、`site`（只生成网站）、`selftest`（检查 OpenAI、SEC、港交所、巨潮能否访问）；`--company <id>` 只处理指定公司，`--events` 强制检索事件。

### 0.4 适配器与分工

| 来源 | 适配器 | 覆盖 | 状态 |
|---|---|---|---|
| 礼来细数据 | `lilly_deep` | 礼来 | 已上线 |
| SEC（10-K/10-Q；20-F 后续） | `sec` | 美股公司及在 SEC 申报的中概股 | 第 1 阶段 |
| 港交所披露易 | `hkex` | 港股公司（中报、年报） | 第 3 阶段 |
| 巨潮资讯 | `cninfo` | A 股公司（一季报、半年报、三季报、年报） | 第 3 阶段 |

适配器的约定：只返回行和核对结果，不直接写统一格式文件；状态放在 `state/<公司>/`；GPT 统一用 `ctx.gpt`，事件检索前看 `ctx.gpt_ok("events")`；网络或 GPT 的偶发失败只记提醒，可能写错数据时才算“必过”项失败。港股、A 股报告是 PDF，这两个适配器可以用 `pypdf` 读文字（工作流里安装），其余代码只用 Python 标准库。

GPT 的职责：新增公司（按待加清单查清身份，再由程序用 SEC、港交所、巨潮的官方清单核对）、XBRL 科目映射有分歧时提议映射、读 PDF 抽数（每个数都要在原文里找到、报表要平）、产品与业务的中英文命名和分类、每家公司的重大事件和业绩说明（做法见第 8 节）、新术语的中英对照。

### 0.5 页面

首页按 9 个方向（头部药企·美国、头部药企·欧洲、RNA、细胞疗法、罕见病与基因疗法、中国创新药、医疗器械、供应链、计算与 AI）列出公司；横向比较表和通用公司页在第 2 阶段补上。礼来保留现有的细页面。全站中英对照：静态文字直接写在 HTML 里，脚本画的报表行、图例、提示框从 `window.__GLOSSARY__`（`agent/glossary.json`）取英文；没有术语表时只显示中文。

# 礼来细数据流程（`lilly_deep` 适配器）

以下第 1~12 节说明礼来的细数据流程。路径里的 `data/` 指 `data/lly/`，`agent/state.json`、`agent/learned.json` 已移到 `state/lly/`。
---

## 1. 总体结构

```
SEC EDGAR（10-Q / 10-K / 8-K 业绩新闻稿）
        │  sec.py：声明身份、限速、重试、缓存
        ▼
解析 tables.py + extract.py ──► 组装 build.py ──► 核对（必过项 + XBRL 交叉核对）
                                                      │ 全部通过
GPT（OpenAI Responses API）                           ▼
  ├ 联网找重大事件 ──► 规则核对 ──────────────────► data/ 7 个数据文件 ──► 全量核对 ──► 网页 _site/ ──► GitHub Pages
  ├ 业绩新闻稿里的一次性项目 ──► 原文与数字核对 ──┘
  ├ 第四季度价格/销量拆分 ──► 原文、加总、增速核对
  └ 新产品的治疗领域 ──► 只能从 5 个领域里选
```

| 路径 | 作用 |
|---|---|
| `data/` | 看板读取的 7 个数据文件（见第 2 节）。2026Q3 及以前来自礼来财务数据表（已逐项核对），之后由流程自动追加 |
| `page/index.html`、`page/calcs.js`、`page/app.js` | 页面结构与样式、所有派生数字的计算、所有图形的绘制。Claude 看板和独立网页用的是同一份 |
| `agent/pipeline/` | 自动维护程序（只用 Python 标准库） |
| `agent/web/` | 独立网页需要的运行时（`dash-shim.js`）和配色（`theme.css`） |
| `agent/config.json` | 公司、SEC、事件、GPT、核对容差等设置 |
| `agent/state.json` | 已处理的季度、回测结果、上次更新事件的日期等（由程序维护，随数据一起提交） |
| `agent/learned.json` | GPT 判定过的新产品治疗领域（判定一次就固定下来，以后不再问） |
| `agent/tests/` | 测试与固定样本（真实申报文件里的表格、2026Q3 时的数据快照） |
| `.github/workflows/update.yml` | 每天运行的工作流 |
| `AGENTS.md` | 给编程助手（例如 Codex）的改代码规则 |

### 每天的流程（由 `agent.core.run auto` 调用；也可以单独运行 `python -m agent.pipeline.run auto`）

1. 读 SEC 上礼来的申报清单（CIK 0000059478）。
2. 找出 `data/` 最新季度之后、已经结束的季度。每个季度需要两份文件：业绩 8-K（Item 2.02，附件 EX-99 是新闻稿）和 10-Q（第 1~3 季度）或 10-K（第 4 季度）。只要还缺一份，就记为“尚未发布”，第二天再看，这不是错误。
3. **回测**：在追加新季度之前（以及代码改动后、或距上次回测超过 30 天时），用同一套解析器重新解析 2025Q4~2026Q3 这 4 个已核对季度，结果必须与 `data/` 一致。回测不过，说明 SEC 文件格式或代码有变化，本次不追加任何新季度。
4. 解析并组装新季度，逐项核对（第 7 节）。任何“必过”项不通过，这个季度整季不写。
5. 写入后，让 GPT 读业绩新闻稿，看有没有要标注的一次性项目（第 8.2 节）。
6. 每 14 天（或刚追加了新季度时）让 GPT 联网找新的重大事件，每条再单独核对一次日期（第 8.1 节）。
7. 对 `data/` 做全量核对（第 7.4 节），不通过就不保存任何修改。
8. 生成网页 `_site/index.html`，写报告 `agent/output/report.md`（也显示在 Actions 运行页面上）。
9. 工作流提交数据变化、发布网页；如果有“需要处理”的问题，就开（或追加评论到）带 `dashboard-bot` 标签的 issue。

## 2. 数据文件

金额单位一律是**百万美元**；增速、构成是**小数**（0.41 = 41%）；空格子表示“没有披露”，不是 0。CSV 为 UTF-8、逗号分隔、LF 换行。

| 文件 | 每行是 | 字段 | 来源（2026Q4 起） |
|---|---|---|---|
| `income_statement.csv` | 一个季度 | quarter, period_end, revenue, cost_of_sales, gross_margin, rnd, msa, acquired_iprd, impairment_restructuring, operating_income, other_net, pretax_income, income_tax, net_income, eps_diluted, diluted_shares_k, ng_gross_margin, ng_operating_income, ng_net_income, ng_eps_diluted | 8-K 新闻稿的利润表（当季列）和非 GAAP 调节表 |
| `income_annual.csv` | 一个年度（或年初至今） | year, months, period_end + 上面同样的利润表字段 | 8-K 新闻稿的年初至今/全年列。当年未满 4 个季度时，同时保留当年和上年“相同月数”两行，供同比 |
| `balance_sheet.csv` | 一个季度末 | quarter, period_end, cash_and_sti, accounts_receivable, inventories, other_current_assets, total_current_assets, investments, goodwill_intangibles, ppe, other_noncurrent_assets, total_assets, short_term_debt, accounts_payable, sales_rebates, other_current_liabilities, total_current_liabilities, long_term_debt, other_noncurrent_liabilities, total_liabilities, total_equity, total_liabilities_equity | 10-Q / 10-K 的合并资产负债表 |
| `product_revenue.csv` | 一个季度的一个产品 | quarter, area, product, us, intl, total | 10-Q 收入附注的分产品表；第 4 季度 = 10-K 全年 − 第 3 季度 10-Q 的前三季度；再加上 8-K“重点产品”（见 6.3） |
| `price_volume.csv` | 一个季度的一个地区 | quarter, period_end, region, revenue, price, rate, volume, total_change | 10-Q 的“收入变化构成”表；地区收入来自分产品表的 Revenue 行 |
| `price_volume_annual.csv` | 一个年度的一个地区 | year, months, region, revenue, price, rate, volume, total_change | 10-Q 的年初至今列 / 10-K 的全年表 |
| `events.json` | 一个事件 | id, date, quarter, type, product, title, title_en, url | GPT 联网检索 + 规则核对（第 8 节） |

治疗领域固定为 5 个：Cardiometabolic Health（心血管代谢）、Oncology（肿瘤）、Immunology（免疫）、Neuroscience（神经科学）、Other（其他）。
事件类型固定为 6 个：获批、并购、业绩说明、定价与可及、临床、产能。

## 3. 页面各部分

页面从上到下按“结论 → 趋势 → 结构 → 去向 → 资产 → 增长 → 产品 → 报表 → 事件”排列。所有部分都跟着页头选中的**期间**变：季度（如 2026Q3）或年度（如 2025；当年未满四个季度时是年初至今）。点击任一图里的柱子或格子，会把整页切换到那个期间。

下面每一部分都写了：**做什么**、**数据与计算**、**呈现与交互**。图形名（`data-draw`）和计算名（`dash.calc`）写在括号里，方便对照代码。

### 3.1 页头
- **做什么**：告诉读者现在看的是哪个期间，以及这一期最重要的几个数字。
- **数据与计算**：`kpi`（营收、同比、营业利润率）、`mix_p`（替尔泊肽占比）。
- **呈现与交互**：小字公司名与“季度财务，金额单位亿美元”；衬线大标题“礼来财务看板”；一句话摘要（期间名称 + 营收 + 同比 + 替尔泊肽占比 + 营业利润率，数字全部来自计算）；两个下拉框选年份和季度（`ysel`、`psel`，季度下拉里有“全年/年初至今”），旁边是“回到最新季度”按钮（只在没选最新季度时出现）；下面一行小字说明数据范围（`qtext`）。

### 3.2 核心指标（6 张卡片）
- **做什么**：一眼看清规模、增长、盈利能力和每股收益。
- **数据与计算**：`kpi` 计算从利润表得出每个期间的营收（亿美元）、同比、毛利率、研发费用率、营业利润率、净利润、稀释每股收益、非 GAAP 每股收益、外购在研；带 `_pp` 的是比率与去年同期相差的**百分点**（计算里已换算好，保留一位小数）。季度与去年同季比；年度与上年**相同月数**比。
- **呈现与交互**：卡片依次是营收、毛利率、研发费用率（附研发投入）、营业利润率（附外购在研金额，提醒它造成的波动）、净利润、稀释每股收益（附非 GAAP）。大数字用衬线体；同比上升为绿色、下降为红色；每张卡片下有一条小折线（`spark`），显示最近若干期的走势并标出所选期间。

### 3.3 收入趋势 + 收入构成
- **做什么**：左边看收入怎么一季一季（或一年一年）长起来，右边看所选期间的收入由什么组成。
- **数据与计算**：`area_p`（按治疗领域）、`series_p`（最近四个季度收入最高的 8 个产品 + “其他产品”；只在最新季度仍单独披露的产品里选）、`mix_p`、`kpi`、`region_p`、`events`。
- **呈现与交互**：
  - 趋势图（`trend`）：堆叠柱状图。切换按钮：按“治疗领域/主要产品”分组（`tv`），看“收入/同比变化”（`tm`，同比变化时向下的部分是减少、横线是合计变化），按“季度/年度”（`tg`），可勾选叠加营业利润率折线（`ol`）。柱子上方的小记号是当季的关键事件：圆点＝获批、菱形＝并购、方块＝业绩说明、三角＝定价与可及、星形＝临床、十字＝产能。悬停显示明细；悬停也会让右边的构成图临时预览那个期间。图例在 `trendlegend`。
  - 构成图（`mixdonut` + `mixlist`）：环形图 + 列表，可切换“领域/产品/地区”（`cv`）；中心大数字是总收入；列表列出金额、占比、同比，点产品行会在下方产品详情里打开该产品。

### 3.4 营收去向
- **做什么**：把一块钱营收拆开——成本、研发、销售管理、外购在研、减值、其他、所得税，最后剩下多少净利润。
- **数据与计算**：`cost_flow`（各项金额与占营收比例）。
- **呈现与交互**：一条横向分段条（`flow`），每段宽度＝占营收比例，颜色区分项目；超过营收的部分（亏损期）用斜线纹表示；下面是两列图例表（金额、占比）。悬停某段，其余段变淡。

### 3.5 资产负债表
- **做什么**：所选期末公司有多少资产、欠多少钱、净资产多少，财务是否稳健。
- **数据与计算**：`bs_kpi`（总资产、现金及短期投资、有息负债＝短期借款＋长期债务、净负债、股东权益、资产负债率、流动比率，及同比）、`bs_lines`。季度看当季末；年度看年末，当年未满四个季度时看最近一个季度末（`bsasof` 写明时点）。
- **呈现与交互**：6 个小指标（`bsnum`、`bsdelta`）；下面两条横向结构条（`bsbars`）：资产构成、负债与权益构成，同一时点两条等长，颜色按项目区分，“其他”用中性灰。

### 3.6 资产负债结构趋势 + 资产负债表浏览
- **做什么**：资产（或负债与权益）结构怎么随时间变；以及所选期末的完整报表。
- **数据与计算**：`bs_lines`（22 行，含计算出的非流动资产、非流动负债；每行有金额、占总资产比例、同比、环比）。
- **呈现与交互**：左边堆叠柱（`bstrend`），可切换“资产/负债与股东权益”（`bsv`），折线是资产负债率，点击柱子切换期间，图例在 `bslegend`。右边是可展开的报表（`bsstmt`）：分组可点开看明细，列为金额、占总资产、同比或环比（`cmp`；年度视图只有同比）。“其他”类由合计数减去已列项目得出，每组都能配平。

### 3.7 增长从哪里来（价格 / 汇率 / 销量）
- **做什么**：礼来把收入同比增速拆成销量、价格（净价）和汇率三部分。这一块回答“增长是卖得多了还是卖得贵了”。
- **数据与计算**：`prv_p`（各地区各期的三部分贡献与合计）、`region_p`（所选期间各地区）。
- **呈现与交互**：地区按钮（`rgsel`：合计、美国、美国以外，以及 2026Q3 之前的欧洲、日本、中国、其他地区）；柱状图（`prv`）每个期间三根柱子（销量、价格、汇率），折线是合计增速；没有数值的期间标 NM。右侧小表（`prvreg`）列出所选期间各地区的拆分。颜色图例用 `swatch`。

### 3.8 产品热力图
- **做什么**：每个产品的生命周期和增长节奏。
- **数据与计算**：`product_p`。只显示最近 `HEAT_WINDOW`（4）个季度收入合计不少于 `HEAT_MIN`（1 亿美元）的产品；两个阈值在 `app.js` 里是常量，说明文字里的数字也由它们画出（`heatwin`、`heatmin`）。
- **呈现与交互**：行是产品，列是季度（`heat`）。“收入”模式下颜色深浅按该产品自己最高的季度收入换算；“同比增速”模式下绿色增长、红色下降（`hm`）。点击格子切换到该产品和季度；点击产品名打开产品详情。

### 3.9 产品版图 + 产品详情
- **做什么**：所选期间各产品的相对大小；以及某个产品的完整历史和相关事件。
- **数据与计算**：`product_p`、`area_p`、`events`。
- **呈现与交互**：
  - 版图（`tree`）：矩形树图，按治疗领域分组、按领域配色，方块面积＝收入。点击方块打开产品详情。
  - 产品详情：标题是产品名（`pname`），旁边是领域标签（`parea`）；四个数字（`pnum`：当季收入、同比、占总营收、美国/国际）；柱状图（`pchart`）显示每季美国和国际收入，**只披露合计的季度画一根中性灰的整柱**，图例里出现“只有合计”（`pwhole`）；柱子上方是该产品的事件记号；下面列出相关事件（`pevents`），没有时显示“暂无收录的相关事件”。

### 3.10 利润表浏览 + 关键事件
- **做什么**：完整的利润表，以及所有重大事件的清单。
- **数据与计算**：`is_lines`（每行金额、占营收、同比、环比）、`area_p`、`product_p`、`event_counts`。
- **呈现与交互**：
  - 利润表（`stmt`）：营收可以逐级展开到治疗领域和产品；毛利、营业利润、净利润、每股收益旁边灰字是礼来公布的非 GAAP 数字；同比/环比切换（`cmp`）；基数为负时不计算变化率。
  - 关键事件：按类型筛选的胶囊按钮（`et`，带各类数量 `ecount` 和符号 `glyph`）；表格（`erows`）列出日期、季度、类型、标题（链接原文）、产品；所选期间的事件高亮；点一行把整页切换到该季度。

### 3.11 数据说明（折叠区）
写明数据来源、口径（年度口径、非 GAAP、资产负债表“其他”类的算法、2026Q4 起改用 SEC 披露口径），以及看板尚未包含的内容（现金流量表、研发管线、股价）。这里是静态文字，不放数字。

## 5. 计算规则（`page/calcs.js`）

所有页面上的数字都必须来自数据文件或这里的计算，页面代码里不出现数字常量（阈值常量除外，而且说明文字里的阈值也要从常量画出来）。

| 计算 | 输入 | 输出（每行） |
|---|---|---|
| `kpi` | income_statement, income_annual | 期间、类型、月数、营收（亿）、同比、毛利率及变化（百分点）、研发、研发费用率及变化、营业利润率及变化、净利润及同比、每股收益及同比、非 GAAP 每股收益、外购在研 |
| `area_p` | product_revenue | 期间 × 治疗领域：金额、美国、国际（领域里有只披露合计的产品时留空）、占比、增减额、同比、环比 |
| `series_p` | product_revenue | 期间 × 主要产品（前 8 + 其他产品）：金额、排名、占比、增减额、同比 |
| `product_p` | product_revenue | 期间 × 产品：金额、美国、国际（只披露合计时为空）、亿美元、占比、同比、环比 |
| `mix_p` | product_revenue, price_volume | 期间：美国收入占比（产品没有拆分的期间改用分地区收入）、替尔泊肽金额与占比 |
| `prv_p`、`region_p` | price_volume, price_volume_annual | 期间 × 地区：收入、价格、汇率、销量、合计 |
| `cost_flow` | income_statement, income_annual | 期间 × 去向项目：金额、占营收 |
| `is_lines` | income_statement, income_annual | 期间 × 利润表行：金额、占营收、同比、环比 |
| `bs_kpi`、`bs_lines` | balance_sheet | 期末指标；资产负债表各行 |
| `event_counts` | events | 各类型事件数量 |

通用规则：同比＝本期 ÷ 去年同期 − 1，保留 4 位小数；基数≤0 时不算；比率之差以百分点存储（保留 1 位）；年度只与上年相同月数比较；季度序号用“2026Q3”，年度用“2026”。

## 6. 新季度的取数规则（SEC 口径）

### 6.1 利润表
- 从 8-K 新闻稿里找“同时有 Revenue、Net income 和 % Chg 列”的利润表；表头的月份＋年份必须正好是目标季度（例如“Three Months Ended September 30, 2026”）。
- 列：去掉百分比和 NM 格子后，依次是 [本季, 去年同季, 年初至今, 去年年初至今]；第一季度只有前两列（年初至今＝当季）。
- 字段对应：Revenue；Cost of sales；Research and development；Marketing, selling, and administrative；Acquired IPR&D（没有这一行记 0）；Asset impairment, restructuring and other special charges（没有记 0）；Operating income；Other income (expense)（取合计行，不取利息、其他两个分项）；Income before income taxes；Income tax expense；Net income；Earnings per share - diluted；Weighted-average shares outstanding (thousand) - diluted。毛利＝收入−销售成本。
- 非 GAAP：毛利、净利润、每股收益直接取调节表的 Non-GAAP 行；**非 GAAP 营业利润＝营业利润＋营业层面的调整项**。调整项标签里写着“(Income taxes)”“tax effects”的算所得税层面，写着“(Other income/expense)”的算营业外，其余（摊销、减值重组等）算营业层面。自检：报告净利润＋全部调整项＝非 GAAP 净利润。
- 10-Q 里的利润表用来交叉核对（收入、净利润、每股收益必须一致）。10-K 只有全年数，用来核对 8-K 的全年列。

### 6.2 资产负债表
取 10-Q / 10-K 合并资产负债表第一列（当期期末），按以下规则归类：
- 现金及短期投资＝Cash and cash equivalents＋Short-term investments；应收、存货、投资、物业厂房设备、短期借款（Short-term borrowings and current maturities of long-term debt）、应付、销售返利与折扣、长期债务直接取；商誉与无形资产＝Goodwill＋Other intangibles。
- 其他流动资产＝流动资产合计 − 已列流动资产；其他非流动资产＝总资产 − 流动资产 − 投资 − 商誉无形 − 设备；负债类同理；非流动负债合计用 Total noncurrent liabilities（旧版报表叫 Total other liabilities）。
- 股东权益用 Total equity；没有时用“归属礼来股东权益＋少数股东权益”。

### 6.3 分产品收入
- 第 1~3 季度：10-Q 收入附注里“Three Months Ended”的分产品表，每行 [本期 美国, 美国以外, 合计, 上年 美国, 美国以外, 合计]。第 4 季度：10-K 全年表（[美国 今年, 去年, 前年, 美国以外 今年, 去年, 前年]）减去第 3 季度 10-Q 的前三季度表。
- SEC 附注只单列少数大产品（目前是 Mounjaro、Zepbound、Jardiance、Trulicity、Verzenio、Taltz），其余在各领域的“Other …”里；神经科学和其他领域只给领域合计。这些汇总行改名为 `Other Cardiometabolic Health (combined)`、`Other Oncology (combined)`、`Other Immunology (combined)`、`Other Neuroscience (combined)`、`Other (combined)`，与 2026Q3 以前礼来数据表里的小额“Other …”区分开。
- **重点产品拆分**：8-K 新闻稿的“Selected Products”表给出若干产品的当季合计（例如 Foundayo、Jaypirca、Inluriyo、Ebglyss、Omvoh、Kisunla）。按产品所属领域（已有数据里查；新产品由 GPT 判定一次，记入 `learned.json`），从该领域的 “(combined)” 行减出来单列。拆出的产品和减过的 “(combined)” 行**只有合计、没有美国/国际拆分**（us、intl 留空）；拆分后若 “(combined)” 为负，该领域本季不拆。
- 产品名去掉脚注（“Zepbound(1)”→“Zepbound”）。

### 6.4 价格 / 汇率 / 销量
- 第 1~3 季度：10-Q 的“components of the change in revenue”表，列为 [本季 美国, 美国以外, 合并, 年初至今 美国, 美国以外, 合并]，行为 Volume、Price、Foreign exchange rates、Percent change；“—”是 0。地区收入取分产品表的 Revenue 行。地区名：U.S.、Outside U.S.、Total Revenue。
- 第 4 季度：地区收入＝全年−前三季度；合计增速由收入算出；三部分拆分只在新闻稿正文里，由 GPT 读出并经过核对后才填（第 8.4 节），否则留空。
- 年度：10-Q 年初至今列；10-K 的全年表（含各地区全年收入）。年度表里当年的旧行会被整体替换。

### 6.5 年度利润表
当年未满四个季度时写两行：当年年初至今、上年相同月数；年度结束（第 4 季度）后删除这两行，写当年全年一行。

## 7. 核对规则

### 7.1 每个新季度（“必过”项，任何一项不过整季不写）
- 利润表字段齐全；毛利＝收入−成本；营业利润＝毛利−各项费用；税前＝营业利润＋其他收支；净利润＝税前−所得税（容差 2 百万）。
- 8-K 与 10-Q 的收入、净利润、每股收益一致；第 4 季度 8-K 全年列与 10-K 一致。
- 资产＝负债＋权益；资产合计＝负债和权益合计。
- 分产品合计＝总收入；拆分重点产品前后合计不变。
- 美国＋美国以外＝合计；分地区合计＝利润表收入；第 1~3 季度：三部分之和≈合计变化（±1.5 个百分点）、披露的增速≈由收入算出的增速（±1.1 个百分点）。
- 年初至今收入＝年度利润表收入。
- XBRL 交叉核对：SEC XBRL 数据库里的总资产、季度收入、季度净利润与解析结果一致（取不到时只提醒）。

“提醒”项（不阻止写入，写进报告）：非 GAAP 指标缺失、调节表不自洽、“其他”类为负、产品收入为负、新增单列产品等。

### 7.2 回测
用 2025Q4、2026Q1、2026Q2、2026Q3 四个已核对季度检验解析器（覆盖第 4 季度和第 1~3 季度的全部规则）。利润表、资产负债表逐项一致（每股收益 ±0.01，其余 ±1）；分产品按同口径归并后一致（±2）；地区收入与拆分一致。

### 7.3 GPT 输出
见第 8 节；规则写在 `tasks.py` 和 `verify.py`，GPT 不能绕过。

### 7.4 全量核对（每次保存前）
季度连续无缺；每季度利润表勾稽；资产负债表配平；产品美国＋国际≈合计（±2.5，礼来数据表的“其他”类是倒挤数）；分产品合计≈总收入；分地区合计＝总收入；全年＝四个季度之和；事件 id 唯一、类型合法、网址只来自礼来官网或 SEC。

## 8. GPT 的任务

调用 OpenAI Responses API（`gpt.py`），密钥 `OPENAI_API_KEY`，模型 `OPENAI_MODEL`；没设置模型时按 `config.json` 的偏好列表从账号可用模型里挑，偏好的模型都下线了就自动用账号里版本号最新的通用模型（形如 gpt-5.5，不带 mini、pro 等后缀），报告里会记一笔。需要结构化输出时用 JSON Schema（strict）；模型不支持某个参数时会自动退回（去掉域名过滤、来源列表或结构化输出），但核对规则不变。GPT 写的中文标题统一在中文与英文、数字之间加空格（`verify.cjk_spacing`），和已有标题一致。

2026-11-09 用真实输入实测过（gpt-5.1 为主，gpt-5.5 也试过）：选模型、联网搜索、第四季度拆分（2025Q4 新闻稿，与已核对数据一致）、业绩说明、治疗领域（6 个产品全对）、事件检索（见 8.1）。每次调用 5~15 秒。

### 8.1 重大事件（每 14 天一次，或有新季度时）
- **输入**：检索日期范围（上次最新事件前 7 天和今天前 60 天中较早者 ~ 今天）、已知产品名单、范围内已收录的事件。
- **要求**：联网搜索（限定 investor.lilly.com、lilly.com、sec.gov），只收录获批、并购、定价与可及、临床、产能五类；不要分红、会议或会上展示数据的预告、电话会预告、人事任命。每条给日期（新闻稿电头上的日期）、类型、产品（多个用“、”）、中文标题（不超过 40 字，公司名写“礼来”）、新闻稿原英文标题、网址。
- **核对**：网址必须是礼来官网或 SEC，且必须出现在 GPT 实际检索到的来源里（防止编造网址）；英文标题属于固定的不收录写法（“to showcase/present … data”、dividend、conference call、board of directors、executive committee 等）的直接去掉；日期在范围内；类型合法；与已有事件不重复（同网址，或同日期＋类型＋产品）；中文标题里的数字必须出现在英文原标题里。
- **第二次核对日期**（`tasks.confirm_event`）：前面都通过后，再单独调用一次 GPT，只给网址，让它打开新闻稿逐字读出电头和标题；日期由程序从电头解析（`dateline_date`），必须与检索给的日期一致，标题也要对得上，而且这篇新闻稿必须出现在这次调用的来源里。原因：实测一次检索里 4 条有 2 条日期错了月份（Olumiant 9 月 25 日写成 10 月 25 日，Taltz 8 月 31 日写成 10 月 31 日）。加了这一步以后，两次实测收进的 4 条日期全部与新闻稿一致。礼来官网的 RSS 本来可以直接核对，但它拒绝非浏览器访问，不能用。
- **漏检**：每次检索只能找到范围内的一部分新闻稿（实测每次 1~3 条，而且每次不同），所以每 14 天检索一次、回看 60 天，每条新闻稿有约 4 次被找到的机会。每次最多收 6 条。id 形如 `e2026-11-12-mounjaro`。

### 8.2 业绩说明（每个新季度一次）
- **输入**：8-K 新闻稿全文。
- **要求**：判断本季度收入或利润里有没有需要提醒读者注意的特殊项目（出售权益收入、里程碑款、返利估计大额调整、巨额外购在研、税法变化）。有的话写一句中文（金额用“亿美元”），项目名称照新闻稿的说法翻译，并逐字摘录支撑每个数字的原句。
- **核对**：每句摘录必须原样出现在新闻稿里；中文里的每个金额、百分比、每股金额都要能在摘录里找到（“4.1 亿美元”对“$410 million”）；中文里说“一次性”的，摘录原文必须写了 one-time 或 non-recurring（实测时 GPT 曾把外购在研费用说成“一次性”，礼来原文并没有这么说）。事件日期为 8-K 日期，季度为所报告的季度，类型“业绩说明”，网址为新闻稿在 SEC 的地址。

### 8.3 新产品的治疗领域（遇到时一次）
输入是新闻稿里提到这个产品的每一处前后文（最多 4 处，`tasks.product_context`；只看第一处常常不够，例如 Inluriyo 第一次出现在 CEO 的一句话里）。GPT 结合自己对该产品的了解，不确定时联网搜索 lilly.com 查适应症。只能从 5 个领域里选，拿不准选 unknown（这时该产品留在 “(combined)” 里，不单列）。判定结果记入 `learned.json`。

### 8.4 第四季度的价格/销量拆分
- **输入**：第四季度 8-K 新闻稿全文。
- **要求**：读出美国、美国以外、全球的销量、价格、汇率贡献和合计（百分数），并逐字摘录原句。新闻稿没写的项填 null，不许用合计减其他项推算。礼来的写法通常不全，例如 2025 年第四季度：美国写了销量 +50%、价格 −7%；美国以外只写了销量 +38%、汇率 +4%（没写价格）；全球只写了销量 +46%、价格 −5%（没写汇率）。
- **核对**（`tasks.part_supported`，每一项单独核对）：原句逐字在新闻稿里；原句按逗号、and、offset by 等切成分句，某项的数字必须和这一项的关键词（volume / price / exchange rate）在同一个分句里、分句里没有别的项，增减方向也要一致（decrease、lower、unfavorable 为负）。对不上的项留空并在报告里提醒，其余照收；美国的汇率影响按定义为 0。三项都有时，销量＋价格＋汇率≈合计（±1.5）；合计≈由收入算出的增速（±1.1）。一项都核实不了的地区整体不用，季度只保留由收入算出的合计增速。

### 8.5 费用
实测（gpt-5.1）：一次事件检索连同日期核对约 2~4 万输入 token、2~5 次联网搜索，约 5~10 美分；每家公司每 14 天一次。全部约 70 家公司时每月约 10 美元，每月上限 15 美元（见第 0.3 节）。每季度几次短调用（业绩说明、第四季度拆分、新产品归类）各约 1~2 美分。报告里记录每次运行的调用次数和 token 数。

## 9. 自动运行

- **时间**：每天 13:23 UTC（`.github/workflows/update.yml`），也可以在 Actions 页面手动运行，并选择模式：auto、events、backtest、check、selftest、site。
- **密钥与设置**（仓库 Settings）：Secret `SEC_USER_AGENT`（SEC 要求写明身份，例如 `Lilly Dashboard you@example.com`）、Secret `OPENAI_API_KEY`、Variable `OPENAI_MODEL`（可选）；Pages 的 Source 选 GitHub Actions。
- **失败处理**：流程退出码为 1 时工作流开一个带 `dashboard-bot` 标签的 issue，正文就是报告；问题没解决之前，后续失败追加评论，不重复开 issue。网页仍然发布（用最后一次通过核对的数据）。
- **偶发问题不打扰人**：SEC 偶尔访问不了只提醒，连续 3 天才算问题；GPT 失败只提醒，不影响财务数据更新；文件还没发布不算问题。
- **保持定时任务活跃**：GitHub 会停用 60 天没有活动的仓库的定时任务。流程每 14 天更新一次事件检索日期、每 25 天写一次心跳，都会提交到仓库。
- **缓存**：从 SEC 下载的归档文件缓存在 `agent/.cache`（不提交），代码不变时一直复用。

## 10. 出问题时怎么办

| 报告里写的 | 原因 | 处理 |
|---|---|---|
| “尚未发布：10-Q / 业绩 8-K” | 礼来还没提交 | 不用管，每天会再看 |
| “没有认出 资产负债表 / 分产品收入表 …（格式可能变了）” | SEC 文件格式变了 | 打开报告里的文件，对照 `extract.py` 的找表规则（第一列标签）更新；跑 `python -m agent.pipeline.run backtest` 和测试，通过后提交。可以把 issue 交给编程助手按 `AGENTS.md` 处理 |
| “解析器回测没通过” | 代码改动或 SEC 文件变化 | 看回测列出的差异项，修正解析规则 |
| “XX 有核对未通过，整季不写入” | 某项勾稽不平（多为新的报表行或标签变化） | 看“XX 核对”一节列出的项目 |
| “无法访问 SEC（连续第 3 次）” | `SEC_USER_AGENT` 没设置或被拒 | 检查密钥是否写了真实联系邮箱 |
| “重大事件更新失败（GPT）” | 密钥、额度或模型问题 | 手动运行 selftest 模式查看 |

## 11. 修改页面或程序的规则

- 页面（`page/`）的样式只用设计变量，所有 CSS 类以 `ly-` 开头。
- **一写者规则**：静态文字写在 `index.html`；脚本只在带 `data-draw` 的元素里写内容。
- **数字只来自数据或计算**：页面代码里不写死任何财务数字；说明文字里提到的阈值必须由脚本常量画出来。
- 改了 `calcs.js` 或 `app.js` 后，用 `python -m agent.pipeline.run site` 生成网页并在浏览器里检查；Claude 看板版本用的是同一份文件，需要时把 `page/` 下三个文件同步过去。
- 改了 `agent/pipeline/` 后，必须跑：`python -m unittest discover -s agent/tests -t .`，有网络时再跑 `python -m agent.pipeline.run backtest`。
- 不要手工改 `data/` 里 2026Q3 及以前的数据（那是已核对的基准，也是回测的标准答案）。如确需更正，同时更新 `agent/tests/fixtures/seed/` 并说明原因。

## 12. 已知限制

- 2026Q4 起，产品明细只到 SEC 披露的粒度（约 6 个大产品＋新闻稿里的重点产品＋各领域“其他”），重点产品和 “(combined)” 行没有美国/国际拆分；地区只有美国、美国以外、全球。2026Q3 及以前保留礼来财务数据表的完整明细。礼来投资者关系网站有防机器人保护，程序不会绕过，所以拿不到它的财务数据表。
- 第四季度的价格/销量拆分依赖 GPT 从新闻稿正文读出，读不出时只有合计增速。
- 重大事件只收录礼来官网和 SEC 的来源，可能漏掉只在其他媒体报道的事件。
